# BIZ-002: 予約承認

事務局による仮予約の承認・却下、直接予約の作成・変更、メッセージ送受信を担うコンテキスト。

事務局の権限は団体内ロール（VAR-001）とは別の軸にあり、団体への所属に関わらず全団体・全予約に及ぶ（COND-009）。判定の根拠は INFO-006.is_staff である。

事務局は予約を削除できない。取りやめる場合は事務局キャンセルまたは却下で、理由とともに記録を残す。削除すると予約詳細ごと消え、団体が「いつ・なぜ無くなったか」を確かめられなくなるためである（GOAL-007）。事務局による承認・却下・キャンセル・直接作成・直接変更は操作履歴（BIZ-007）に記録され、事務局権限によって初めて許された操作は団体側に「事務局」と表示される（COND-012）。メッセージの送信（UC-009）は操作履歴の対象外である（メッセージ自体に送信者と日時が残る）。そのため、送ったメッセージは編集も削除もできない（COND-023）。

相手方の動き（メッセージ・承認・却下・キャンセルなど）は、メールで知らせる（EVT-005〜008・EVT-017）ほか、確認するまでダッシュボードに未読として出す（UC-037・COND-026）。出すのは「まだ見ていないこと」であり、「返信が要ること」ではない。返信待ちを状態として持つと、やり取りを終えた後も、最後に受け取った側にずっと残り続けるためである。やり取りの単位は予約そのものとし、要件ごとのスレッドや、スレッドを閉じる操作は設けない。予約が終われば、やり取りも自然に終わる。

## 業務フロー

### BUC-006: 仮予約の承認・却下

```mermaid
sequenceDiagram
    actor 事務局
    participant システム
    actor 団体

    システム-->>事務局: 仮予約申請通知メール（EVT-001）
    事務局->>システム: 仮予約一覧またはダッシュボード（SCR-022）の承認待ちを確認
    alt 承認
        事務局->>システム: 承認を実行
        システム-->>団体: 承認通知メール送信（EVT-005）
    else 却下
        事務局->>システム: 却下理由を入力して却下（必須）
        システム-->>団体: 却下通知メール送信（EVT-006）
    end
    システム-->>団体: 確認するまでダッシュボードに未読として表示（UC-037・COND-026）
```

### BUC-007: 承認済み予約の事務局キャンセル

```mermaid
sequenceDiagram
    actor 事務局
    participant システム
    actor 団体

    事務局->>システム: 予約一覧から承認済み予約を選択
    事務局->>システム: キャンセル理由を入力してキャンセル（必須）
    システム-->>団体: キャンセル通知メール送信（EVT-007）
```

### BUC-008: 事務局による予約の直接作成・変更

```mermaid
sequenceDiagram
    actor 事務局
    participant システム
    actor 団体

    alt 直接作成
        事務局->>システム: 空き状況（SCR-001）から枠を選び予約申請・変更フォーム（SCR-002）で承認済みとして作成
        Note over システム: 即時「承認済み」ステータスで作成（メール通知なし）
        システム->>システム: Google Calendar に登録（EVT-009。COND-024）
    else 直接変更
        事務局->>システム: 一覧（SCR-003）または予約詳細（SCR-005）から予約申請・変更フォーム（SCR-002）を開き内容を変更
        Note over システム: ステータスは変えずに更新（承認済みは承認済みのまま、仮予約は仮予約のまま。再承認不要）
        opt 承認済みの予約の施設・日時を変えた
            システム->>システム: Google Calendar に反映（日時は EVT-011、施設は変更前から削除〈EVT-010〉し変更後に登録〈EVT-009〉。COND-024）
        end
        システム-->>団体: 事務局による予約変更通知メール送信（EVT-017。申請者・管理者宛て）
    end
```

### BUC-009: 予約へのメッセージ送受信

```mermaid
sequenceDiagram
    actor 事務局
    participant システム
    actor 団体

    alt 団体側として送る（自団体のメンバー。役割は問わない。その団体に所属する事務局を含む）
        団体->>システム: 予約詳細（SCR-005）で本文を入力して送信（COND-023）
        システム-->>事務局: メッセージ通知メール送信（EVT-008。本文と予約詳細へのリンク）
        システム-->>事務局: ダッシュボードに未読として表示（UC-037。事務局の誰かが返信するか予約を操作するまで、全員に）
        事務局->>システム: 予約詳細でメッセージを確認（開いた本人の分が既読になる）
    else 事務局として送る（その団体に所属しない事務局。sent_as_staff = true）
        事務局->>システム: 予約詳細（SCR-005）で本文を入力して送信（COND-023）
        システム-->>団体: メッセージ通知メール送信（EVT-008。申請者・団体管理者全員と、この予約に送ったことのある団体側の利用者へ。いずれも全項目を見られる人に限る。送信者は「事務局」と表示）
        システム-->>団体: 同じ相手のダッシュボードに未読として表示（UC-037）
        団体->>システム: 予約詳細でメッセージを確認（既読になる）
    end
    Note over 事務局,団体: 送信者本人には通知しない。送ったメッセージは編集・削除できない（COND-023）。未読の判定は COND-026
```
