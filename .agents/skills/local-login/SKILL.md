# ローカルでログインする

このアプリにパスワードは無い。ログインはメールの認証コードかパスキーだけ。
ローカルでは認証コードのメールを送らず（開発サーバーのターミナルに出すだけ）、
Better Auth が D1 の `verification` 表に平文で保存する。`pnpm -s run dev:otp` はそこから読む。

パスキーは使わない。パスキーの操作をすると OS のダイアログ（Windows Hello など）が開き、エージェントでは先へ進めないため。

特に、ログイン画面（`/login`）は**開いただけで**パスキーの問い合わせを始める（入力欄のオートフィルに出すため）。
Claude Code の内蔵ブラウザでは、これが Windows の「パスキーを使用してサインインします」というダイアログになって画面の最前面に出て、
並行して作業している人を遮る。だから、1 の 4 でオートフィルを止めるまでは、ログイン画面もログインが要るページ（ログイン画面へ転送される）も開かない。

## 1. 準備を確かめる

1. 開発サーバーが `http://localhost:5173` で動いていること。
   - ページの origin は `.dev.vars` の `BETTER_AUTH_URL`（既定は `http://localhost:5173`）と完全に一致させる。
     `http://127.0.0.1:5173` や、5173 番が埋まっていて 5174 番などで立ち上がったサーバーでは、ログインが `INVALID_ORIGIN`（403）で失敗する。
2. 開発サーバーと**同じフォルダ**で `pnpm -s run dev:otp` を実行し、シードの人物の一覧を出す。
   「DB に無い」と出た人がいたら `pnpm run db:migrate:local` → `pnpm run db:seed` で入れる。
3. ブラウザで `http://localhost:5173/api/auth/ok` を開く。`{"ok":true}` と出るだけの、アプリの画面ではないページで、
   パスキーの問い合わせをしない。ここから先の JavaScript は、このページの上で実行する（同じ origin から fetch するため。`about:blank` のままでは送れない）。
4. このブラウザのパスキーのオートフィルを止める（ブラウザごとに 1 度だけ。印は localStorage に残る）:

   ```js
   localStorage.setItem("iclub-reserve.dev.passkey-autofill", "off");
   ```

   印のあるブラウザでは、ログイン画面を開いてもパスキーの問い合わせをしないので、ダイアログは出ない。
   効くのは開発サーバー（`pnpm run dev`）だけ（`app/lib/auth/dev-passkey-autofill-switch.ts`）。
   人と共用しているブラウザ（Claude in Chrome で操作する Chrome など）には入れない。人がそのブラウザで確かめるときのオートフィルまで消えるため。
   元に戻すときは `localStorage.removeItem("iclub-reserve.dev.passkey-autofill")`。

5. ブラウザがすでにログインしていることがある（内蔵ブラウザは Cookie を持ち越す）。
   `await fetch("/api/auth/get-session").then((r) => r.json())` を実行し、
   `user.email` が使いたい人ならログインは要らない。ログインしていなければ `null` が返る。

## 2. 誰でログインするか選ぶ

`dev:otp` には人物の名前かメールアドレスを渡す。立場の正しい説明は `scripts/seed/seed-data.ts` の `seedPersonas` のコメントにある。

| 人物                | 立場                                   | 向いている確認                                 |
| ------------------- | -------------------------------------- | ---------------------------------------------- |
| `staff`             | 事務局。どの団体にも入っていない       | 予約の承認・施設の管理・監査ログ・事務局の画面 |
| `groupAdmin`        | 有効な団体の管理者                     | 予約の申請・団体の管理・招待                   |
| `groupMember`       | 有効な団体の一般メンバー               | 管理者だけの操作が出ないこと                   |
| `noGroupUser`       | どの団体にも入っていない               | 何も無いときのダッシュボード                   |
| `pendingGroupAdmin` | 承認待ちの団体だけに入っている管理者   | 予約の申請の導線が出ないこと                   |

## 3. ログインする（ふつうはこちら: ページの上で fetch する）

ログインの画面そのものを確かめるのでなければ、こちらを使う。画面を操作せずに済み、パスキーを勧める画面も通らない。
ページの上で JavaScript を実行できる道具（Claude Code の内蔵ブラウザの `javascript_tool`、Claude in Chrome、Playwright の `page.evaluate` など）を使う。

1. 1 の 3 で開いた `http://localhost:5173/api/auth/ok` のまま進める。`/login` は開かない。
2. 認証コードを送る（ページで実行。`200` が返る）:

   ```js
   await fetch("/api/auth/email-otp/send-verification-otp", {
     method: "POST",
     headers: { "content-type": "application/json" },
     body: JSON.stringify({ email: "staff@osaka-u.ac.jp", type: "sign-in" }),
   }).then((r) => r.status);
   ```

3. 認証コードを読む（シェルで実行。標準出力には 6 桁の数字だけが出る）:

   ```bash
   pnpm -s run dev:otp staff
   ```

4. ログインする（ページで実行。`123456` を 3 の数字に置き換える。`200` が返れば、ログインの Cookie がブラウザに入っている）:

   ```js
   await fetch("/api/auth/sign-in/email-otp", {
     method: "POST",
     headers: { "content-type": "application/json" },
     body: JSON.stringify({ email: "staff@osaka-u.ac.jp", otp: "123456" }),
   }).then((r) => r.status);
   ```

5. 確かめたいページへ移動する。

## 4. ログインの画面から入る（ログインの画面を確かめるとき）

1. 1 の 4 でオートフィルを止めてから、`http://localhost:5173/login` を開く。「メールアドレス」欄に入れて「メールアドレスで続ける」を押す。
2. 「認証コード」欄が出て**から** `pnpm -s run dev:otp <人物>` を実行し、出た数字を入れて「認証する」を押す。
   欄が出る前に読むと、前に送った古い認証コードを読んでしまうことがある。
3. パスキーの登録を勧める画面が出たら「あとで」を押す。登録のボタンは押さない。

## 5. 別の人に切り替える

先にログアウトしてから、3 をやり直す。ログアウトせずにログインし直しても切り替わるが、前の人のセッションが DB に残り、
アカウント設定のセッションの一覧（UC-031）に増えていく。

```js
await fetch("/api/auth/sign-out", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: "{}",
}).then((r) => r.status);
```

## うまくいかないとき

| 症状                                             | 原因と対処                                                                                                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| fetch が 403 `INVALID_ORIGIN`                    | ページの origin が `BETTER_AUTH_URL` と違う。`http://localhost:5173` のページから送る                                                                              |
| 送信が 403 `EMAIL_DOMAIN_NOT_ALLOWED`            | アカウントが無く、阪大のアドレスでもない人。シードの人物を使う                                                                                                     |
| `dev:otp` が「認証コードがありません」           | 送る前に読んだ／アドレスの打ち間違い／開発サーバーが別のフォルダ（別の worktree）で動いていて DB が別物。開発サーバーを動かしているフォルダで実行する              |
| `dev:otp` が「ローカル DB が見つかりません」     | マイグレーションをしていない。`pnpm run db:migrate:local` → `pnpm run db:seed`                                                                                     |
| ログインが `INVALID_OTP`・`OTP_EXPIRED` など     | 古い認証コードを入れた、5 分の期限（`OTP_EXPIRES_IN_SECONDS`）が切れた、間違えすぎた。3 の 2 から送り直す                                                          |
| ログインの後に `/welcome` へ送られる             | 利用規約に同意していない人。シードの人物は同意済みなので、自分で作った人なら初回設定を済ませる                                                                     |
| Windows の「パスキーを使用してサインインします」 | 1 の 4 の印を入れずに、ログイン画面（ログインが要るページからの転送を含む）を開いた。人に知らせてダイアログを閉じてもらい、印を入れてから開き直す                  |

## 守ること

- 使うのはローカルの開発サーバーだけ。プレビュー（`*.iclub-preview.gdgoc-osaka.jp`）や本番では使わない。
  `dev:otp` が読むのはローカルの D1（`.wrangler/state`）だけで、ほかの環境の認証コードは読めない。
- ログインに使うのはシードの人物か、ローカルで作ったテスト用の人だけ。実在の人のメールアドレスを使わない。
- E2E テストには使わない。E2E は別の DB（`.wrangler/e2e-state`）と、`e2e/support/fixtures.ts` の `signInAs` を使う。

## なぜこの形か

アプリに「誰としてでもログインできる」開発用の入口を足せば 1 回の移動で済むが、設定を間違えてデプロイしたときに誰でも入れてしまう。
この手順は本物のログインの流れをそのまま通る。認証コードの読み方は E2E と共通（`scripts/lib/otp.ts`）。

アプリに足したのは、開発サーバーでだけ効く、パスキーのオートフィルを止める印だけ。
エージェントのブラウザかどうかを User-Agent で見分けて自動で止める手もあるが、見分け方がブラウザの作りや版に縛られるうえ、
人が同じ種類のブラウザで確かめるときまで止まってしまう。そのため、止めたいブラウザに印を入れる形にした。
