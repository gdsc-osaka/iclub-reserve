# ADR-009: 日本の祝日カレンダーの同期と空き状況表示への反映

## ステータス

提案 (2026-10-14)

## コンテキスト

空き状況カレンダー（`/availability`）では、施設・設備の空き枠を曜日ごとに視覚的に把握できるよう、日付見出しおよびタイムライン列の面色を土曜は青系、日曜は赤系で色分けしている。
しかし、日本の祝日（成人の日、ゴールデンウィーク、山の日、振替休日など）については平日の色・表記のままとなっており、祝日に利用・申請したい利用者にとって休日の直感的な把握が難しいという課題があった。

そこで、空き状況カレンダーにおいて日本の祝日を日曜と同じ赤系で表示し、曜日表記を「月・祝」のように表現する機能の導入を検討した。
祝日判定の実現にあたっては、以下の制約と要件を満たす必要がある。

1. **実行環境の制約（Cloudflare Workers / Edge）**:
   Node.js 固有の API や巨大なファイル読み込みに頼らず、軽量かつエッジで高速に動作すること。依存パッケージをむやみに増やさないこと。
2. **画面表示の高可用性と耐障害性**:
   空き状況カレンダーの表示時に外部 API へ同期通信を行ってはならない。外部サービスに障害や遅延が発生しても、カレンダー画面の表示が妨げられてはならない（画面表示の成否を外部依存させない）。
3. **祝日データの正確性と持続性**:
   祝日法の改正や振替休日・国民の休日に対応し、手動メンテナンスの手間なく自動的に最新データが維持されること。
4. **祝日と祭日の明確な区別**:
   一般的な「祝日（国民の祝日および振替休日）」のみを対象とし、七夕や節分、母の日といった「祭日・年中行事」は休日に含めないこと。

## 決定

**Google が公開している日本の祝日カレンダー（iCal 形式）を外部依存パッケージなしで日次定期処理（Cron）にて取得し、D1 の `holiday` テーブルにキャッシュする。空き状況カレンダーの画面表示では D1 のみを参照する。**

### 1. 取得元の選定理由と代替案の比較

祝日データの取得元として、Google の公開 iCal（`https://calendar.google.com/calendar/ical/ja.japanese%23holiday%40group.v.calendar.google.com/public/basic.ics`）を採用した。

| 案                                    | メリット                                                                                                                                                                                                                        | デメリット / 採用しなかった理由                                                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Google 公開 iCal（採用）**          | - 認証不要の公開 URL で取得可能<br>- 2021〜2031 年など複数年分が網羅されている<br>- 祝日法の改正や振替休日が Google 側で継続的にメンテナンスされる<br>- RFC 5545 に準拠したテキスト形式で、外部ライブラリなしで容易にパース可能 | - 祝日以外に「祭日」も含まれるため、抽出時のフィルタリングが必要（後述）                                                                                                |
| **コード内に固定の祝日表を持つ**      | - 外部通信が不要で最も高速かつ確実                                                                                                                                                                                              | - 毎年の祝日法改正や春分の日・秋分の日、特例措置、将来の祝日追加のたびにコード修正・デプロイが必要になる                                                                |
| **内閣府の公式 CSV（国民の祝日）**    | - 国の公式データである                                                                                                                                                                                                          | - Shift_JIS で提供されており、Workers 上で文字コードを変換する手間が増える<br>- iCal と違い決まった書式の規格が無く、列の並びが変わったときに読み解き側を直す必要がある |
| **npm パッケージ（holiday-jp など）** | - 関数 1 つで手軽に判定できる                                                                                                                                                                                                   | - パッケージの更新が止まった場合に将来の祝日に対応できなくなる<br>- バンドルサイズが増加し、プロジェクトの「依存を増やさない」制約に反する                              |

### 2. 祭日の除外と振替休日の扱い

Google の公開カレンダーには、国民の祝日だけでなく「七夕」「節分」「ひな祭り」「母の日」「七五三」といった「祭日・年中行事」も含まれている。
調査の結果、Google の iCal では以下の明確な区別が存在する：

- **祝日（および振替休日）**: `DESCRIPTION:祝日`
- **祭日**: `DESCRIPTION:祭日\n祭日を非表示にするには、...`

このため、iCal のパース処理（`toHolidayListFromIcal`）では `DESCRIPTION:祝日` と完全一致する VEVENT のみを抽出する。
これにより、祭日を除外しつつ、「建国記念の日 振替休日」などの振替休日を漏れなく祝日として取り扱う。

### 3. 日次での D1 入れ直しと耐障害性

- 毎日日本時間 4:00（UTC 19:00）の日次 Cron Trigger（`CRON_DAILY_RECONCILE`）において、カレンダー突き合わせ処理とは独立した try/catch で祝日更新ユースケース（`refreshHolidaysUseCase`）を実行する。片方が失敗してももう片方は影響を受けない。
- 祝日一覧の入れ替えは、1 回の `db.batch()` 内で不可分（atomic）に行う。D1 のバインドパラメータ上限（100 個）を遵守するため、INSERT は 50 行以下のチャンクに分割して投入する。
- **画面（`/availability`）の表示処理では、D1 の `holiday` テーブルのみを読み取る**。Google カレンダーへの問い合わせは一切発生しないため、Google 側の一時的な障害やネットワーク不通時でもカレンダー画面は通常通り開くことができる。

### 4. 異常データ時の保護（0 件ガード）

Google 側のレスポンス異常やネットワーク障害により、取得した iCal から読み解いた祝日件数が 0 件になった場合、既存の D1 データを削除・更新せず、エラー（`HolidayErrorCode.EmptyHolidays`）として即座に中断する。
これにより、外部の一時的な不具合によってすでに正常に保持されている祝日データが吹き飛ぶ事故を防止する。

### 5. 運用上の留意事項

- **デプロイ直後の挙動**:
  マイグレーション適用直後は `holiday` テーブルが空である。そのため、最初の定期バッチ（日本時間 4:00）が走るまでの間は祝日色・表記が反映されない（平日の色・表記となる）。
- **手動同期エンドポイント**:
  ローカル開発環境では cron が動かないため、開発専用エンドポイント `POST /dev/refresh-holidays`（`APP_ENV === "local"` 限定）で手動で取り込む。プレビュー・本番では使えないので、デプロイ直後は次の日次処理を待つ。
