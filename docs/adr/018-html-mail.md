# ADR-018: メールの HTML 化と文面改善

## ステータス

採用 (2026-11-10)

Issue #276 を受けて決める。

## コンテキスト

- これまでメールはプレーンテキストのみで送信していた。重要な案内やアクション（予約詳細への遷移や招待の承諾ボタン）が埋もれやすく、視認性に課題があった。
- 予約の通知の本文に載せていた予約 ID は 24 文字あり、場所を取っていた。予約 ID は画面のどこにも出しておらず、利用者は ID では予約を探せない。
- 送信インフラ（`MailDraft.html` → `mail_outbox.body_html` → `MailMessage.html` → SMTP）はすでに HTML に対応済みであり、HTML 本文を生成する仕組みだけが不足していた。

## 決定

### 1. 共通の構造 `MailContent` からテキスト版と HTML 版を生成する

- メールの中身を表す共通の構造型 `MailContent` を定義し、各メールの組み立て関数はこれを 1 度だけ構築する。
- `toMailBodies`（中で `toMailText` と `toMailHtml` を呼ぶ）により、同じ構造からテキスト版と HTML 版の両方を生成する。
- HTML は Transactional Outbox に積む時点で生成して `body_html` に保存する（ADR-002 の「積んだ時点の文面で送る」原則を維持）。
- 送信プレビューやローカルログ、Discord 連携、E2E テストのためにテキスト版も維持する。

### 2. 安全で堅牢な HTML メールのレンダリング

- 利用者入力値のエスケープは `toMailHtml` 内の 1 箇所（`escapeHtml`）で集約して行い、XSS を防止する。
- メールクライアントの表示崩れを防ぐため、`<table role="presentation">` によるレイアウトとインラインの `style` 属性のみを使用する。外部 CSS・`<style>`・クラス名・CSS 変数・画像・JavaScript・外部フォントは使用しない。
- 配色はライトモード前提の 16 進カラーコードで固定し、ダークモード強制反転等による視認性低下を防ぐ meta タグを設定する。
- アクションリンクの URL は安全性を検証し、`http://` または `https://` で始まらない場合はボタン（`<a>` 要素）を出力せずテキストとして扱う。

### 3. 本文の予約 ID を整理し、リンク URL に集約する

- 本文の独立した項目としての「予約ID」行を削除し、予約詳細ページへのリンク URL に含まれる予約 ID で識別するように簡素化する。

### 4. 開発時の確認用ルート `/dev/mail-preview` の提供

- ローカル環境専用（`APP_ENV === "local"`）のリソースルートとして `dev/mail-preview` を配置し、各種メールの HTML 版およびテキスト版の表示・エスケープ結果を目視確認できるようにする。

## 採らなかった案

- **React Email の導入**: 新たな外部依存パッケージが増えるため採用を見送った。
- **react-dom/server を用いた JSX テンプレート**: ドメイン層の純粋関数を `.tsx` にする必要があり、かつメールクライアント向けには Tailwind がそのまま使えないため、プレーンな文字列組み立て関数の方がシンプルで保守しやすいと判断した。
- **HTML 版のみにする**: Discord への通知投稿やローカルコンソール出力、E2E テストがテキスト版を参照しているため、両方を維持する必要がある。

## 影響

- `/dev/mail-preview` は、ほかの開発専用ルートと同じくログイン不要のパス（`PUBLIC_PATHS`）に足す。返すのは見本の値で組み立てた文面だけで、ローカル以外ではルート自身が 404 を返す。
- 余白は `div` ではなく `td` に付ける。Outlook は `div` の `padding` を読まないためである。
- 移行前にすでに Outbox に積まれていた未送信のメールは、保存されているテキストのまま送信される。
