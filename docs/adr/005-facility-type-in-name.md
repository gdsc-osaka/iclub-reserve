# ADR-005: 施設の種別・キャンパス・建物をフィールドで管理せず名称に含める

- **ステータス**: Accepted
- **決定日**: 2026-03-18
- **決定者**: GDG on Campus Osaka 開発チーム
- **関連 RDRA**: INFO-002, REQ-022, REQ-025

---

## コンテキスト

予約対象には部屋（C棟2階、豊中試作室）と設備（3Dプリンター、レーザーカッターなど）が混在し、さらに吹田・豊中の複数キャンパスにまたがる。施設一覧を表示する際に利用者が「何を・どこで」予約しているか判別できる必要がある。

以下の区分をフィールドとして管理するか、名称に含めるかが論点となった。

- **設備種別**: 部屋 / 設備（3Dプリンター・レーザーカッターなど）
- **キャンパス**: 吹田 / 豊中
- **建物**: C棟、試作室など

## 選択肢

| 案 | 方式 | 採否 |
|----|------|------|
| **A（採用）** | 種別・キャンパス・建物をすべて施設名称に含める（例:「吹田：3Dプリンター 積層タイプ」「豊中試作室：3Dプリンター」） | ✅ |
| B | `type`（部屋/設備）フィールドを持つ | ❌ |
| C | `campus`（吹田/豊中）や `building` フィールドを持つ | ❌ |
| D | B + C を組み合わせた複合フィールド構成 | ❌ |

### 案B・C・D を却下した理由

- 現在の予約対象施設・設備は8件と少なく、種別・キャンパス・建物による絞り込みや集計の要件が存在しない
- 施設数が少ないため、名称に含めるだけで一覧表示において十分な識別が可能
- フィールドを増やすとスキーマ・UI・バリデーションの複雑さが増す割に、現時点での利益が少ない
- 将来的に施設数が増え絞り込みが必要になった場合は、その時点でフィールド追加のマイグレーションを検討できる

## 決定

**INFO-002 に種別・キャンパス・建物の独立フィールドを持たず、すべて `name`（施設名称）に含める。**

### 命名規則（例）

| 名称 | 含まれる情報 |
|------|------------|
| `吹田：C棟2階占有 イベント予約` | キャンパス（吹田）＋建物（C棟2階）＋用途 |
| `吹田：3Dプリンター 積層タイプ` | キャンパス（吹田）＋設備種別＋型番区別 |
| `豊中試作室` | キャンパス（豊中）＋建物 |
| `豊中試作室：3Dプリンター` | キャンパス（豊中）＋建物＋設備種別 |

## 影響・トレードオフ

| 項目 | 内容 |
|------|------|
| 絞り込み・検索 | 種別・キャンパス・建物での絞り込みはクライアント側での文字列マッチングに依存する。施設数が増えた場合はフィールド追加を検討する |
| 命名の一貫性 | 名称に情報を含める運用のため、施設登録時に命名規則を統一する必要がある（事務局の運用ルールとして管理） |
| 将来の拡張 | 施設数の増加やキャンパス間の比較が必要になった場合、`name` の変更なしに `campus` 等のフィールドを追加できる |
