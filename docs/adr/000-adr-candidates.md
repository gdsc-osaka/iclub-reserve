# ADR 候補リスト

決定済みの ADR（ADR-001〜006）に加え、実装フェーズに入る前に議論・記録すべき設計判断の候補を管理する。

> **運用ルール**: 決定が確定したものは番号を採番して `NNN-*.md` として記録し、本リストから削除する。未決定のまま実装を進める場合も「未決定である」ことを明示してここに残す。

---

## 未決定の候補

### ADR-007 候補: データストア選定

**論点**: バックエンドのデータストアとして何を使うか。

| 選択肢 | 特徴 |
|--------|------|
| Firestore | Firebase / Google Cloud ネイティブ。スキーマレスで柔軟だが、複雑なリレーション・トランザクションは得意でない |
| Cloud SQL（PostgreSQL） | リレーショナル DB。予約・メンバーシップ・メッセージなど正規化されたデータモデルに適合しやすい |

**関連 RDRA**: INFO-001〜006（全エンティティ）

---

### ADR-008 候補: バックエンド実行基盤

**論点**: バックエンド API をどの基盤で動かすか。

| 選択肢 | 特徴 |
|--------|------|
| Cloud Run | コンテナベース。常時起動可能でコールドスタートが少ない |
| Cloud Functions | イベントドリブン。Google Calendar 連携のトリガー処理に適合しやすい |
| Firebase Functions | Firebase エコシステムとの親和性が高い |

**関連 RDRA**: BIZ-005（カレンダー連携）、EVT-009〜011

---

### ADR-009 候補: フロントエンドホスティング

**論点**: フロントエンドをどこでホスティングするか。

| 選択肢 | 特徴 |
|--------|------|
| Firebase Hosting | Google インフラに統一できる。CDN・カスタムドメイン対応 |
| Cloud Run（SSR） | サーバーサイドレンダリングが必要な場合に有効 |

---

### ADR-010 候補: メール送信基盤

**論点**: 通知メール（EVT-001〜008、EVT-013）を何で送信するか。

| 選択肢 | 特徴 |
|--------|------|
| Firebase Extensions（Trigger Email） | Firestore ドキュメントをトリガーにメール送信できる。SendGrid 等と組み合わせる |
| SendGrid（直接利用） | 豊富なテンプレート機能・配信ログ |
| Resend | シンプルな API。React Email 等との親和性が高い |

**関連 RDRA**: EVT-001〜008, EVT-013

---

### ADR-011 候補: 環境分離と IaC

**論点**: 開発・ステージング・本番の環境分離をどう管理するか。Terraform 等の IaC を導入するか。

**関連**: ADR-002（Secret Manager）、ADR-007〜010（各インフラ選定）
